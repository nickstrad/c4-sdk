### Source Playwright intermittency (recorded, not hidden)

With default parallelism on this shared 4-core VM (load average about 4-5 from other sessions) the candidate suite failed intermittently in five of five runs, with a varying set of 1-4 failures, all `30s` timeouts or focus assertions: `navigation.spec.ts:92` (desktop new-tab), `navigation.spec.ts:15` (mobile), `context.spec.ts:24` (mobile), `component-docs.spec.ts:9` (mobile). Evidence:

- The baseline `316c4b6` (old toolchain) also failed on 1 of 3 default-parallel runs, in the same two navigation tests (`source-playwright-base-316c4b6*.log`), and passed 65 on the other two. The toolchain bump is therefore not the cause.
- Each failing test passed in isolation (`navigation.spec.ts:92` twice, `component-docs` mobile once), and the whole suite passed 65/65 serially.
- Nick's ruling (2026-10-15, `/root/c4-lead-mobile-nonblocking.md`): the mobile component-docs failure is non-blocking and must be noted; it recurred across C4-07, C4-10 and this rehearsal. The navigation and context failures are the same load-sensitive timeout class, not waived by that ruling but not reproduced serially or in isolation. They are an unresolved test-reliability limitation, not a product defect shown by any serial run; recommended follow-up is a separate item to harden these specs (or the CI worker count). No test was weakened.

## Limitations and warnings

- Supported combination is exactly what was exercised: Node `22.23.2` on Linux x64, React/React DOM `19.3.0`, TypeScript `6.0.3`, Vite `8.3.4`, Chromium. Other versions, OS, browsers, SSR/hydration and other bundlers are not claimed.
- `0.x` is not a 1.0 stability guarantee (see `public-api.md`).
- The package ships a ~1.1 MB CJS/ESM bundle and a ~2.1 MB self-contained layout worker; Vite emits chunk-size warnings for consumer builds of the demo.
- Source Playwright intermittency above.
- The copied-project consumer workflow formerly planned as C4-09 has been removed by Nick; this release makes no copy-consumer claim and does no ts-db work. Any ts-db module ingestion is a separately owned future milestone. `work-scripts/node/copy-project` and `tests/copy-consumer` remain as unshipped internal remnants; they are outside the package and not a supported workflow.
- npm `whoami` returned `nickstrad` per Twin; this report did not run it. A 2FA prompt may still occur at publish.
