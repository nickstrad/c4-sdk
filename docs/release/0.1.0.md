#### Correction `fix/p-06-browser-evidence` (tests only; artifact unchanged)

Mechanism, reproduced under a bounded CDP renderer CPU slowdown (rate 4, one worker, retries off): the target card is outside the visible canvas (it is "Inspect Continuity", "Inspect Local Git repository", or the Cursor "Open detail for Continuity" link); Playwright's native scroll-into-view races React Flow's `wrapperOnScroll`, which resets the wrapper scroll to zero, so the click is intercepted by the pane or another node, or times out. This agrees with the independent mobile investigation (`/tmp/c4-mobile-docs-evidence/`, `external-mobile-investigation.md`). Before the fix, with slowdown rate 4, these failed: `navigation.spec.ts` desktop new-tab and mobile drill, `context.spec.ts` invalid-replacement (desktop and mobile), `showcase.spec.ts` mobile Cursor guided reading. At normal speed (rate 1) they all passed, so slowdown is a timing probe, not a VM-load model.

Fix: before each pointer click on a canvas node, the three specs focus the target so the viewer's existing focus-reveal pans it into view, assert `toBeInViewport()`, then deliver the same real click (including the Control-click that opens a new tab). No forced click, synthetic event, sleep, retry, timeout change or config change; all route/focus/history/explanation assertions are unchanged.

After the fix: same slowdown rate 4, whole three-spec set: 26 passed (the only failure, "generic production viewer", needs port 4174 that the scratch config does not serve, and fails identically before the fix); six affected tests x3 at rate 4: 36 passed; four affected tests x2 at rate 6: 16 passed; real config, full source suite `--workers=1`: 65 passed, 1 skipped. Not fixed or explained: the mobile `toBeFocused` failure after Up (baseline `-a`, `navigation.spec.ts:36`) and the mobile component-docs focus assertion did not reproduce under slowdown and remain open; the waived component-docs spec was not edited. Evidence: `/tmp/c4-p06-fix-evidence/`, [item record](../../agent-work/items/P-06-browser-fix/STATE.md).

## Limitations and warnings

- Supported combination is exactly what was exercised: Node `22.23.2` on Linux x64, React/React DOM `19.3.0`, TypeScript `6.0.3`, Vite `8.3.4`, Chromium. Other versions, OS, browsers, SSR/hydration and other bundlers are not claimed.
- `0.x` is not a 1.0 stability guarantee (see `public-api.md`).
- The package ships a ~1.1 MB CJS/ESM bundle and a ~2.1 MB self-contained layout worker; Vite emits chunk-size warnings for consumer builds of the demo.
- Source Playwright intermittency above (corrected).
- The copied-project consumer workflow formerly planned as C4-09 has been removed by Nick; this release makes no copy-consumer claim and does no ts-db work. Any ts-db module ingestion is a separately owned future milestone. `work-scripts/node/copy-project` and `tests/copy-consumer` remain as unshipped internal remnants; they are outside the package and not a supported workflow.
