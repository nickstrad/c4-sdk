# Source API and limits

Import public React components and schema/domain functions from `src/lib/c4/index.ts`, and import `src/lib/c4/styles/c4.css` once in the host. This project is consumed by copying source; it has no published npm package. See the root [README](../../README.md) for the tested composition example and code input format.

`decodeArchitecture(input, limits?)` returns a `Result<ValidatedArchitecture>` with precise diagnostic paths. Successful values are normalized and frozen. The editor `architectureJsonSchema` describes shape; runtime decoding also checks references, containment, source URL safety, and resource limits. Editor validation alone is insufficient.

`DecodeLimits` lets a host lower `maxElements` (default 5,000), `maxRelationships` (10,000), `maxDiagrams` (200), `maxJsonDepth` (32), and `maxScenarioJsonDepth` (96). Options must be positive integers no greater than those defaults. Invalid configuration returns a `resource-limit` diagnostic at `$.limits`. JSON depth counts object/array layers from the root; the larger dynamic-scenario budget does not raise semantic nesting limits: groups, code ancestry and scenario steps still have depth 32, and scenarios have at most 1,000 steps.

`createFetchLoader(fetch?, limits?)` supports `maxBundleBytes` (5 MiB), `maxCatalogBytes` (256 KiB), and `decode: DecodeLimits`. It validates configuration when created, forwards cancellation, checks both advertised and actual streamed bytes, rejects invalid UTF-8/JSON, and cancels/releases readers. Byte limits may only be lowered. Inject the loader through `CatalogViewer`; replacing its catalog/loader aborts prior requests and cannot publish stale resources.

`ArchitectureViewer` requires `validatedBundle`. Optional `diagramId` is an initial choice; an injected `RoutePort` owns the actual routed view. The seven wrappers are `SystemLandscape`, `SystemContext`, `ContainerDiagram`, `ComponentDiagram`, `CodeDiagram`, `DynamicDiagram`, and `DeploymentDiagram`; each rejects a routed kind mismatch. All accept the same source viewer props except `expectedKind`.

Compose `ArchitectureProvider`, `DiagramNavigation`, `DiagramView`, `DiagramLegend`, and `DiagramDocumentation` for a host-specific page. `useViewerController` reads the existing provider; it does not create another controller. Navigation, legend, and documentation slots receive props and callbacks. Views render these props; route/domain decisions stay in hooks and pure selectors. Pair a separate `DiagramLegend` with `DiagramView legendSlot={() => null}` to avoid duplicate keys.

A `RoutePort` exposes a stable snapshot until route/history availability changes, subscriptions, codec-aware links, and history actions. Native modified anchor clicks keep browser behavior. `LayoutPort.layout` receives scene membership, generation, abort signal and optional measurements/revision. Responses must echo generation/revision; accepted geometry must retain validated object references, membership and endpoints. Rejected or stale geometry cannot replace the scene. See [contracts](../plans/batch-c-contracts.md).

The built-in ELK adapter is available at `src/lib/c4/adapters/layout/client.ts`. `createElkLayoutPort(workerFactory?, limits?)` permits lower node/edge ceilings (5,000/10,000), cache entries (24), and a configured default timeout (10 seconds). Request `timeoutMs` overrides that default; finite positive values are bounded by the browser timer maximum. Abort/timeout/error terminates the worker and removes handlers/listeners. The cache stores only geometry, evicts oldest insertion when full, and reattaches current validated objects. Optional `geometry: GeometryLimits` lowers published coordinate/extent bounds from 10,000,000 coordinate/span units, sections/bends have per-edge bounds and total routed points are limited to 100,000; these are safety guards, not a performance promise.

Initial framing uses all scene bounds when that remains readable, otherwise centers the first declared card at readable scale. Fit includes routed edges and labels, with zoom down to 0.02. Such an overview can make text too small; keyboard focus reveals a card at readable scale, Actual size restores scale 1, and the complete text alternative preserves every declared relationship/member. Very large scenes can exceed the Fit minimum scale. A saved viewport is restored on return. Focus and viewport memory each keep at most 256 recently saved views per mounted viewer slot; older entries fall back to initial framing. No promise that every node is readable in the initial mobile viewport is made.

Markdown documentation permits safe links and literal text only; no user HTML/images/components execute. Draft STE diagnostics are advisory, with human review still required. The narrow-screen explanation trigger precedes the canvas visually and opens a keyboard-accessible responsive sheet.
